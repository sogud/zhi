# 纸 · Zhi 设计规范

状态：0.3.0 Preview，26 个 Web 组件。PC、TV、iPad 与双屏场景的规则属于设计规范，尚不代表已提供对应原生组件或完成设备验收。

纸的调性是现代中式：以排版、留白、对齐和墨色层次呈现中国审美，以明确的状态、精确的操作和及时反馈呈现现代科技感。先协调字重、比例、间距和操作层级，再考虑局部装饰。笔墨纸砚、印章、竹、雪、云、雨是可探索的审美参考，不是官网或组件必须出现的图案清单。

## 中国审美与现代科技

两者共同服务于内容与操作，不把界面分成“中式装饰”和“科技特效”两部分。

| 设计方面 | Zhi 的表达 |
| --- | --- |
| 排版 | 以端正的左边界、基线和疏密建立秩序；宋体只用于少量近距展示标题，操作和数据使用清楚的无衬线字体 |
| 留白 | 按任务区分组，给主要内容和主要操作留出空间；留白随内容密度与观看距离调整，不追求所有端相同的空白比例 |
| 色彩 | 纸白、墨色和克制的朱色建立层次，青竹作为可选主题；数据、选择、错误和焦点按语义表达，不靠装饰色区分 |
| 表面 | 平整背景、少量边界与微圆角；浮层只增加识别层级所需的对比，默认不叠加纸纹、玻璃、金属或光效 |
| 图标与数据 | 使用统一笔画和视觉重心；数值等宽、数值列右对齐，状态旁有明确文字 |
| 交互 | hover、focus、pressed、selected、disabled 分开定义；反馈由用户操作触发，优先让人看清发生了什么 |

科技感来自信息组织、操作效率和反馈的准确性。霓虹、发光、复杂渐变、悬浮粒子与装饰性仪表不是默认表达。中式气质也不依赖毛笔字、印章、山水或竹叶的组合。

## 主题

- 白纸：清白、明晰，适合日常工具。
- 宣纸：温润的纸白与墨色，适合阅读和书写。
- 墨纸：深色表面与暖白文字，适合夜间使用。
- 青竹：可选的沉静绿色配色，不要求搭配竹叶或竹节图案，主题 ID 为 `qingzhu`。

同一端的四个主题共用尺寸、组件结构和交互；颜色通过语义变量切换。跨端保留语义角色和层级，按平台分别定义尺寸与操作方式。`design/tokens.json` 当前是 Web tokens 的唯一来源，`registry/themes/zhi.css` 由脚本生成；尚未包含 TV 或 iPad 的原生尺寸配置。

`pnpm tokens:build` 同时生成 `registry.json` 中 theme 条目的 CSS 与 `cssVars`。这些字段随 token 更新，其余组件条目手工维护。

## Web 排版与空间

- 正文及控件使用 Noto Sans SC；展示标题少量使用 Noto Serif SC。网页通过 Fontsource 本地依赖加载字体。
- 正文 14/24，标签 14/20，辅助文字 12/20，章节标题 20/30，展示标题 32/48。
- 间距基于 4 px，常用 8、12、16、24、32、48、64 px。
- 默认控件高 36 px，小号高 28 px；控件默认 4 px 微圆角，容器默认 8 px 微圆角。圆角服务于视觉协调与操作识别，不用“纸的外形”推导所有控件必须直角。
- Checkbox 保持方正；Switch 与 Radio 保留熟悉的控件形状。几何形状服务于识别和操作，不按纸张外形机械套用。
- 左边界、文字基线、标签和输入区域保持一致；数值列右对齐。

实际组合的形状对照见[阅读与写作设置页](studies/settings.md)：2/4 px 与 4/8 px 使用相同内容和布局比较。

更多组合见[阅读与草稿管理](studies/application-examples.md)，检查列表、正文、编辑、选择、浮层和反馈在同一界面中的协调性。

## 多端设计

共享品牌和设计原则，分别适配窗口大小、观看距离、输入方式与平台习惯。TV 不能当作放大的 PC；iPad 也不能只用桌面控件缩放得到。

| 场景 | 信息与布局 | 操作重点 |
| --- | --- | --- |
| PC | 内容区配合导航或辅助栏；阅读限制行长，表格保持数值列对齐；窄窗口按内容需要收起辅助区 | 鼠标与完整键盘操作；快捷键有可发现的菜单入口，必要操作不只在 hover 时出现 |
| iPad | 宽窗口可用导航、列表和详情；窗口变窄或文字变大时按优先级收为两栏或单栏，保留当前内容与输入 | 触摸、键盘、指针并用；手势与 Pencil 是增强能力，主要操作有可见入口 |
| TV | 低密度、少层级、短标签，以内容和一组主要操作为中心；文字与控件按原生 TV 字体和远距阅读重新设计 | 方向键、确认和返回；焦点明确、路径可预测，关闭浮层和返回列表时恢复原焦点与滚动位置 |
| 双屏 / 折叠 | 可选的列表—详情、阅读—札记布局；每个内容区完整落在可用屏幕内，避免正文与主要操作跨过铰链 | 展开、折叠、旋转和回到单屏时保留选择、编辑和阅读位置；没有可靠分屏信息时退回普通响应式布局 |

双屏与折叠设备的设计指导不绑定特定设备尺寸或旧版 SDK。

### 尺寸、字体与单位

- PC Web 沿用现有 36 CSS px 控件高、4/8 CSS px 圆角与 4 CSS px 间距基准。遇到触摸输入时按实际点击范围调整，不把控件可见外形等同于触控目标。
- Zhi 的 iPad 触控目标默认采用至少 44 × 44 pt，这是本系统的设计起点，不是所有 Apple 控件的官方最小值。正文优先使用原生文字样式并支持 Dynamic Type，不能把固定高度裁切作为适配方式。
- TV 使用平台的原生 TV 字体与控件尺寸，按实际观看距离评审。正文和焦点标签不用细宋体、极细笔画或桌面 12/14 px 辅助文字。墨纸可作为 TV 的首个设计方案，其他主题仍需分别检查远距可读性。
- Web 的 CSS px、Apple 的 pt、Android 的 dp/sp 分别记录，不按物理分辨率直接互换。同样是 4/8 的几何节奏，不代表各端最终尺寸必须相同。

### 状态与反馈

- 所有端区分“焦点停在哪里”和“什么已经被选中”。颜色之外，用轮廓、填充、图标或文字表达状态。
- PC 和外接键盘场景保留可见焦点及合理的 Tab 顺序。iPad 不依赖 hover 或长按暴露主要动作。
- TV 的方向键导航按行、列与分组组织，非交互文字不占焦点。焦点轮廓即时出现，边缘留出足够空间避免被裁切；轻微缩放可选，不能成为唯一提示，也不覆盖相邻内容。
- 动效解释展开、切换、保存等操作，不模拟飘雪、落雨或书写特效。开启减少动态效果时保留静态状态差异，移除不必要的位移和缩放。
- 弹层的关闭、返回和焦点恢复遵循目标平台习惯；TV 的返回键不机械等同于 Web 的 Escape。

例如同一个阅读任务，PC 可以并排显示清单、正文与札记；iPad 根据窗口在单栏与多栏之间切换；TV 以选书、继续阅读和少量内容操作为主，长文编辑放到合适的近距设备；双屏则可将正文与札记分开。任务关系一致，屏幕结构分别设计。

### 参考与实现范围

平台约束参考 [Apple iPadOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-ipados)、[Apple Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)、[Android TV 焦点系统](https://developer.android.com/design/ui/tv/guides/styles/focus-system)与 [TV 布局](https://developer.android.com/training/tv/playback/compose/layouts)。双屏的分区原则参考 [Microsoft 的历史双屏设计文档](https://learn.microsoft.com/en-us/previous-versions/dual-screen/introduction)，不将其视为当前 SDK 选型建议。以上平台约束与本节的 Zhi 设计选择分开理解。

当前 Registry 仍提供 React / Base UI Web 源码。原生 iPad、Android TV、tvOS 或双屏适配需要对应平台的组件和焦点实现；本节尚未新增运行时、全局缩放模式或设备检测。跨端尺寸和布局需先经具体页面评审，再加入正式 tokens，不能把网页缩放预览当作设备验收。

## 整体协调与装饰

默认界面使用平整、干净的表面和克制的墨色层次。官网不展示意象清单，不叠加印章、竹影、纸纹或歪斜纸片。组件不自动附带纸纹、界栏或自然图案。

印章、竹、雪、云、雨与笔墨纸砚可以影响配色、疏密和节奏，不意味着要画出对应物件。只有具体页面确实需要插图，或使用者明确要求某种装饰时，再选择合适素材并检查整体协调。不要预先把云绑定到空状态、雨绑定到加载、竹绑定到设置页。

现有 SVG、纸纹、界栏类和 seal 按钮变体保留为可选资源；示例默认使用基础组件。保留素材不等于推荐把它加入每个项目。优先保持阅读和操作清楚，装饰不遮挡文字、不拦截点击、不承担状态含义。

## 组件范围

Figma：主题对照、色彩和文字样式、间距规范、Button、Input、Checkbox、Switch 的可编辑组件及状态示例。基础组件的主组件与评审实例分区保存。

代码：26 个组件、四个主题、可交互预览与 Registry 构建。当前目录及组合 API 见 [组件目录](components.md)。

0.2 新增 Textarea、Label、RadioGroup、Select、Card、Badge、Separator、Alert、Progress、Tabs、Accordion、Dialog。当前表单使用 36 px 控件高；卡片和弹窗使用 24 px 内边距，使用克制的微圆角。Tabs 通过字色与底边区分选中状态，Accordion 通过间距和分隔线组织内容。Select 和 Dialog 的浮层继承页面主题；键盘、禁用、焦点管理交给 Base UI。

Progress 支持明确进度和未知进度；未知进度使用静态短条及文字说明，避免持续动画。Alert 默认是静态提示，动态紧急信息可显式传入 `role="alert"`。朱色用于错误与焦点，状态同时通过文字或语义属性表达。

首轮评审检查：中英文和长标签可读；默认、焦点、禁用与错误状态有区别；主题切换后主要操作清楚；留白与对齐在真实组合中成立。

Figma 当前保留 0.1 历史设计：100 个变量、6 个文字样式、12 组主组件、72 个状态变体，覆盖最初四个组件和原有三个主题，仍含旧圆角。新增组件、当前圆角规则、青竹主题与自然素材以当前源码、tokens 和资源目录为准，尚未同步成 Figma 主组件。文件及组件 ID 保存在 `design/figma.json`，后续优先更新已有节点。

Figma 使用本项目自有组件与变量。可访问的社区 UI kit 不属于「纸」的设计资产，不引入其默认视觉规范。

设计资源与代码同用 MIT 许可，目录及使用方式见 [design/README.md](../design/README.md)。仓库保留原有三主题组件 SVG、评审图、变量和文字样式快照，并提供新的原创自然素材。历史快照不作为当前 token 来源；SVG 不保留 Figma 的组件关系，原生 `.fig` 文件尚未导出。字体继续遵循独立的 SIL OFL 1.1 许可。
